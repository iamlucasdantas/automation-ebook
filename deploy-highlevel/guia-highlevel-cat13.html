O que esse gatilho faz

Dispara imediatamente quando um novo registro é criado em qualquer objeto personalizado — imóvel, contrato, projeto, lead qualificado, produto ou qualquer entidade que você modelou no HighLevel.

É o ponto de entrada das automações de Custom Objects. Assim que o registro existe, você pode notificar times, criar tarefas, disparar sequências ou atualizar campos dependentes automaticamente.

Quando usar na operação
Caso 01
Novo imóvel cadastrado
Registro de Imóvel criado → notificar corretor responsável + criar tarefa de vistoria + adicionar ao pipeline.
Caso 02
Novo contrato gerado
Registro de Contrato criado → enviar email de boas-vindas ao cliente + criar task pro time jurídico + atualizar campo "Status" para "Em análise".
Caso 03
Novo projeto aberto
Registro de Projeto criado → notificar gerente no Slack + criar checklist de onboarding + adicionar contato associado à sequência de kickoff.
Filtros disponíveis
Tipo de Objeto
Object Type
principal
Define qual objeto personalizado dispara o gatilho. Cada objeto que você criou (Imóvel, Contrato, Projeto…) aparece como opção.
Impacto: Crie um workflow separado por tipo de objeto pra manter automações organizadas e fáceis de debugar.
Campos Customizados
Custom Fields
condicional
Filtra pelo valor de campos específicos do objeto — por exemplo, apenas imóveis do tipo "Apartamento" ou projetos com "Prioridade = Alta".
Impacto: Permite criar workflows segmentados sem precisar de condicionais dentro do fluxo.

02
Custom Objects

Registro Atualizado

Custom Object Record Updated
Tempo realCustom Objects
O que esse gatilho faz

Dispara quando qualquer campo de um registro de objeto personalizado é atualizado. Você pode filtrar por campo específico — por exemplo, só disparar quando o campo "Status" muda de "Em análise" para "Aprovado".

É o gatilho de estado — reage a transições no ciclo de vida do objeto. Perfeito pra pipelines de aprovação, contratos que avançam de fase, projetos que mudam de status ou imóveis que recebem proposta.

Quando usar na operação
Caso 01
Contrato aprovado
Status do Contrato atualizado para "Aprovado" → enviar email ao cliente + notificar financeiro + mover para próxima etapa do pipeline.
Caso 02
Proposta recebida
Campo "Valor da Proposta" preenchido no objeto Imóvel → alertar corretor + criar task de análise + registrar no histórico.
Caso 03
Projeto concluído
Status do Projeto atualizado para "Concluído" → disparar pesquisa de satisfação + criar relatório final + enviar certificado se houver.
Filtros disponíveis
Tipo de Objeto
Object Type
principal
Define qual objeto personalizado monitorar. Selecione o objeto cujos registros você quer rastrear atualizações.
Impacto: Um workflow por objeto mantém a lógica isolada e evita conflitos entre automações de entidades diferentes.
Campo Alterado
Field Updated
principal
Especifica qual campo deve ser alterado para o gatilho disparar. Sem esse filtro, qualquer edição no registro ativa o workflow.
Impacto: Fundamental pra evitar loops e disparos acidentais. Sempre filtre pelo campo de estado (ex: "Status", "Fase", "Etapa").
Valor do Campo
Field Value
condicional
Define o valor específico que o campo deve ter após a atualização. Ex: Status = "Aprovado" dispara apenas quando o status muda para esse valor.
Impacto: Permite criar workflows específicos por transição de estado sem usar condicionais dentro do fluxo.
